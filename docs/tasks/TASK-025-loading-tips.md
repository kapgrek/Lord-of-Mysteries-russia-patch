### Первопричина (2): совет ставится после нашего однократного прохода
- Панель чинится только событийно: `Open`/`Refresh` базового `UIComponent` (`Init.lua:11984`) → `ProcessOnce` + один отложенный проход через 0.10 с (`panelTextRepair:Queue`, `Init.lua:11112-11135`). Для `P_LoadingDefault` нет ни поздних хуков класса (`LateLabelClasses`, `Init.lua:11831`), ни доп. проходов (`extendedPanelRepairDelays`, `Init.lua:10839`). `RTB_Tips` нигде в `Init.lua` отдельно не упомянут.
- Доказательство — сессия 27.09 (`reference/logs/2026-09-27_1423/Saved/Logs/C7.log`):
  ```
  17:19:23.168 请求打开面板 P_LoadingDefault
  17:19:23.450 event-driven panel repair active for P_LoadingDefault
  17:19:39.987 请求关闭界面 P_LoadingDefault
  ```
  а диагностика (`panel:P_LoadingDefault:walk`, `vis=true`) видит `请关注《廷根市老实人报》…` в **17:19:31** — через 8 с после нашего прохода, панель ещё на экране, ключ в шардах есть. Будь текст на месте во время прохода, `translateTextWidget` перевёл бы его точным ключом.
- 30.09: панель 15:02:14.7–15:02:28.1, наш проход 15:02:15.6, обход в 15:02:31 видит `赞美愚者！` (ключ есть). `hooks.json` s4: `panel:P_LoadingDefault:delayed` runs=3, text_changes=2 — отложенный проход что-то перевёл, но совет на экране потом снова китайский.
- Вывод: игра пишет `RTB_Tips` **позже Open** — либо меняет совет по таймеру (загрузки длятся 9–17 с), либо ставит первый совет асинхронно. В обоих случаях после этого текст больше никто не переводит. Какой из двух вариантов и каким методом — в логах нет (исходников `Loading_Panel` в `reference/` нет, игра о советах в `C7.log` не пишет). Для исправления это не важно (R1 + R2 закрывают оба), для точности — проба R3.
- Записи 25.09 12:04:17 и 26.09 13:20:18 (обход через ~0.5 с после открытия, до нашего прохода) сами по себе могли быть ложными, но 27.09 и 30.09 — нет.

## План

### R1. Поздний хук класса `Loading_Panel` (`Init.lua`)
- В `runtimeFixes.LateLabelClasses` (`Init.lua:11831`) добавить:
  `Loading_Panel = { paths = { { "RTB_Tips" } }, methods = { "^Refresh", "^OnRefresh", "^Update", "^Show", "^Set", "^Play", "Tip", "Timer", "^On" } }`.
  Имя класса — из `owner:P_LoadingDefault/Loading_Panel` (`hooks.json`). После любого такого метода `repairLateLabels` переводит только `RTB_Tips` (обычный `translateTextWidget`, как у остальных late-классов). `OnOpen`/`OnClose` в списке безвредны: правка идёт после вызова и только одного виджета.
- Проверить, что `installLateLabelClassHooks` (`Init.lua:11887`) доходит до `Loading_Panel` (вызывается из обёртки `Open`, `Init.lua:12023`, для не-AutoChess панелей) и что строка `installed late-label class hook Loading_Panel: <методы>` попадает в `C7.log` — это заодно покажет список методов класса.

### R2. Страховка: дополнительные проходы `P_LoadingDefault`
- В `extendedPanelRepairDelays` (`Init.lua:10839`) добавить `P_LoadingDefault = { 1.0, 2.5, 4.0, 6.0, 8.0, 10.0, 13.0, 16.0, 20.0 }` (загрузки 9–17 с; панель маленькая, проход ≤ 5 мс по `hooks.json`).
- Убедиться, что `QueueExtended` срабатывает на **каждое** открытие: состояние по `StateKey` = `userWidget` (`Init.lua:10898`); в логах `WidgetTree_*` у `P_LoadingDefault` разный на каждое открытие, но если виджет переиспользуется, `ExtendedQueued` надо сбрасывать на `Open`. Проход по закрытой/уничтоженной панели уже отсекается (`component.isDestroyed`, `Init.lua:10904`).
- Если R1 по пробе ловит смену совета — R2 оставить как есть (дёшево); убирать не нужно.

### R3. Проба (только при `runtimeFixes.Diag`, `AbsruDiagnostics.lua`)
