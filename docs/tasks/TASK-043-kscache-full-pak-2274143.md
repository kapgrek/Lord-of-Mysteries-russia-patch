# TASK-043: у игрока pakchunk0 хотпатча 2274143 скачан целиком — блок запуска другой, мост не ставится

Чат 1 (анализ), 09.11.2026. Материалы игрока (Telegram): `info.txt`, `installer.log`, `C7.log`, `C7-backup-2026.11.09-07.10.41.log`, `C7-backup-2026.11.09-09.49.53.log`. Сравнение с dev-машиной: `D:\Games\GMZZLauncher\Game\C7\Saved\kscache` (только чтение).

## Симптом
Установщик 3.1.3 и 3.1.4 при каждом запуске пишет: `Проверка кеша: NotFound, версия 2274143, по ключу entry_id блок найден в 2274143/pakchunk0-Windows.pak:40034410, но байты не совпадают (размер пака 112044341)`. Патч не устанавливается, в `C7.log` (все три сессии) нет ни одной строки нашего моста.

## Факты
| | Игрок | Dev-машина |
|---|---|---|
| `AssetsVersion.txt` | 1.2018737.2295021 | 1.2018737.2295021 |
| Папки kscache с pakchunk0 | `2274143` (**112 044 341 байт, полный пак**, 07.11), `2295021` (280 292, дельта) | `2218968` (224 057 784, полный), `2295021` (921 713, дельта) |
| Прочие папки | `2171866` (без pakchunk0) | `2218968`, `2228458`, `2255640`, `2274143` (без pakchunk0) |
| Манифест | `a3450ab3…` | `A3450AB3…` (тот же) |

- Игрок пропустил хотпатчи 2218968–2255640 (последняя его папка до этого — 2171866). Лаунчер не стал собирать цепочку дельт, а скачал pakchunk0 **целиком** в 2274143. У нас блок запуска живёт в полном паке 2218968, а 2274143/2295021 — дельты (урок TASK-039).
- Блок по ключу `entry_id` `e5b5a377c686bc9e96abc007` найден (`InstallerCore.cs:340-351` → `InspectCacheEntry`), первые 64 байта (`original_head_hex`) совпали, но SHA-256 5258 байт ≠ `clean_sha256` `3124ee28…` (`installer/supported_game.json:23`). Это ровно сценарий, описанный в TASK-039:62: «хотпатч перекачает сам блок запуска → ключ останется, байты станут другими → NotFound … нужен новый `cache_launch`».
- Проверка установщика верна: писать наш мост (`bridge/cache-startup.oodle`, собран CPDD под чистый блок `3124ee28…`) поверх других байт нельзя — это порча пака или мост против неизвестного скрипта запуска.
- **CPDD не поможет сейчас:** последний релиз v2.7.5 (24.10) содержит тот же `cache_launch` (`entry_id`, `clean_sha256`, `manifest_sha256` идентичны v2.7.1; `reference/cpdd/v2.7.5/release.json`). Английский патч у этого игрока тоже не встанет.
- **Сами собрать мост не можем:** декомпрессора Oodle нет (`TASK-032-game-update-2218968.md:69`).
- CPDD хранит **полные байты чистого блока** в `release.json → external_bridge.cache_launch.original` (5258 байт). С байтами игрока можно сделать побайтовый дифф и понять масштаб различий (хвост/середина, длина совпадающего префикса).
- Побочное: игрок 3 раза запускал exe 3.1.3, и каждый раз срабатывало самообновление до 3.1.4. Скорее всего, он запускает старый файл заново из `Downloads\Telegram Desktop` или из архива. На проблему не влияет.

## Масштаб
Затронуты все игроки, у которых лаунчер скачал pakchunk0 целиком в 2274143 или позже: вернувшиеся после перерыва и новые установки. Им не поможет ни наш релиз, ни CPDD, пока не появится мост под новый блок.

## План для чата 2 (исполнение)
1. **Сбор данных в установщике** (`installer/LogCollector.cs`, кнопка «Собрать логи»): для каждого кандидата `InspectCache` с совпавшим заголовком, но несовпавшим sha (`CacheHit.HeadOnly` в `info.Hits`, `InstallerCore.cs:398`) класть в архив `cache-block-<ver>-<offset>.bin` — ровно `cache_launch.size` (5258) байт по этому смещению, только чтение (`FileShare.ReadWrite`). В `info.txt` дописать sha256 этих байт. Тест в `tools/InstallerCoreTests` на поддельной папке в `temp/`: пак с блоком «заголовок совпал, хвост другой» → в архиве есть `.bin` нужного размера.
2. **Пока сборка не вышла — инструкция игроку** (выдать пользователю текстом, сам скрипт на ПК игрока не запускаем): PowerShell-однострочник только на чтение, который сохраняет 5258 байт со смещения 40034410 из `Saved\kscache\2274143\pakchunk0-Windows.pak` в файл на рабочем столе, плюс копию `Saved\kscache\local.cache`.
3. **Дифф:** `temp/`-скрипт: байты игрока против `cache_launch.original` из `reference/cpdd/v2.7.5/release.json` → длина общего префикса, число отличающихся байт, sha. Результат записать в раздел «Результат».
4. **Решение по итогам диффа** (в этом чате не решать «на удачу», AGENTS §4):
   - если блок другой целиком/с середины — без Oodle мост не собрать: завести отдельный TASK на сборку моста своими силами (декомпрессор Kraken, например открытый `ooz`, разбор скрипта запуска, повторная упаковка в 5258 байт) или ждать CPDD;
   - сообщить автору CPDD (issue в `Lani27/lord-of-mysteries-english-patch` с хешами блока, без файлов игры) — **только после согласия пользователя**, это внешняя публикация.
5. `docs/LESSONS.md`: «лаунчер качает pakchunk0 целиком, если игрок пропустил несколько хотпатчей; у разных игроков на одной версии игры блок запуска может лежать в разных паках с разными байтами. `cache_launch` должен допускать несколько вариантов чистого блока».
6. Сообщение установщика для `NotFound` с `HeadOnly`-кандидатом: вместо общего «Дождитесь обновления» писать «лаунчер скачал другую сборку блока запуска, отправьте автору архив из „Собрать логи“». Коммит, push. Релиз — по решению пользователя (нужен, чтобы получать `.bin` от других игроков).

**Не делать:** не ослаблять проверку sha в `InspectCacheEntry`, не писать мост поверх несовпавшего блока, не запускать игру и установщик.
