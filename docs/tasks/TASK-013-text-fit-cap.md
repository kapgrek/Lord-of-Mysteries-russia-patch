## Симптом (проверка v2.9.7 в игре, 2026-09-25)
Пользователь: «до настройки размеров было лучше». По 18 скриншотам текст крупнее, блоки разъезжаются и налезают друг на друга:
- Автошахматы: коллекция фигур (подписи синергий и имена), поле (кнопки слева и справа, блок артефактов сдвинут строкой «Экипировка в один клик»), торговая палата, подсказки синергий на полэкрана, выбор артефакта уходит за край экрана;
- навыки (Путь / Соединения / Марионетка): подписи разъехались и наложились, в «Подробностях» название доп. эффекта налезает на описание;
- «Тайное подношение», магазин и инвентарь (левое меню крупным шрифтом), «Рецепт зелья», «Замок» (левые кнопки), «Лёгкие победы».

С dev-флагом `TextFit = "legacy"` на той же v2.9.7 **вид вернулся к v2.9.6** (пользователь, скриншот магазина). Значит, дело только в режиме `measure`. Ранний перевод вложенных компонентов (`EarlyNested`) и удаление мёртвого кода не виноваты.

## Первопричина
Данные сессии v2.9.7 (`report/fit.md`, `overflow.csv`):
- переполнений **1018** против **251** в v2.9.6 (parent 812, both 140, self 66);
- `TextFitMeasured = 11285`, `Shrunk = 1077`, `Failed = 366`, `Deferred = 25779`, `NoEffect = 0`; `TextFitMsMax = 22` мс и `NestedEarlyMsMax = 23` мс (критерий ≤ 8 не выполнен);
- среди переполненных стилизованных: авторский размер **сохранён у 513**, уменьшен у 354.

Причины (`Init.lua`, `runtimeFixes.TextFit`):
1. **Старт с авторского размера.** Пороги v2.9.6 (`TF.Legacy`, `Init.lua:4024+`) заранее опускали почти все заголовки и кнопки до 14–16. `measure` берёт авторский размер (21–27) и уменьшает только при доказанном переполнении.
2. **Мерка «авторазмерного» слота неверна.** Большинство подписей — авторазмерные: `KGHorizontalBox`, элементы списков, кнопки. Если разметки до перевода нет, слот классифицируется **после** разметки русского текста (`Init.lua:3892-3896`: «auto-sized slot then equals its text»). Бюджет = `max(need_pre, parentRoom)` (`:3908-3910`), а родитель к этому моменту уже растянут русским текстом, поэтому `need ≤ budget` и выходит «fits» (`:3916`). Крупный текст раздувает контейнеры, и соседние блоки съезжают.
3. **Текст с переносом при авторазмерной высоте не проверяется вообще** (`:3900`: `slotY ~= "fixed"` → «fits»). Это описания навыков, подсказки синергий, карточки талантов.
4. **Мерка исходного текста есть редко.** `need_pre` (ширина исходного текста до `SetText`) известна только у **298 из 1018** переполненных (29%). У остальных в момент `PreMeasure` ещё нет разметки. Там, где она известна, `need / need_pre`: p10 0,86, медиана 1,48, p90 3,38.

**Вывод:** схема «авторский размер + уменьшение по геометрии родителя» в этой игре не работает, потому что родитель растёт вместе с текстом. Нужны:
- **потолок — размер v2.9.6** (легаси-пороги): хуже v2.9.6 не станет нигде;
- **дополнительное уменьшение** — только по надёжной мерке: фиксированный слот, либо ширина исходного текста `need_pre`, измеренная на разметке исходного текста.

## План
Версия **v2.9.8-RU**, либо следующая свободная: TASK-012 может занять номер, проверь `git log` и `local VERSION`. Новых локальных переменных верхнего уровня не добавлять: VerifyPatch сейчас 179.

1. **Безопасное значение по умолчанию сразу.** `TEXT_FIT_MODE = "legacy"`, отдельным первым коммитом, чтобы `main` не оставался в сломанном режиме. Dev-флаг `TextFit` принимает `legacy` | `cap` | `measure`.
2. **Новый режим `cap`** (`runtimeFixes.TextFit`; переиспользовать `TF.State`, `PreMeasure`, `measure`, `prepass`, отложенную очередь):
   1. **Потолок.** Сначала применить размер и перенос ровно как `TF.Legacy`: пороги, `+2`, `SetAutoWrapText(false)` у заголовков, синергии. Этот размер — `cap` и стартовая точка. Размер никогда не больше `cap`.
   2. **Дополнительное уменьшение**, только если есть надёжная мерка:
      - фиксированный слот, **определённый по разметке исходного текста** (`havePreX > needPreX + 1` в `PreMeasure`) → `budget = haveX`;
      - авторазмерный слот с известной `need_pre` → `budget = need_pre × 1,15` (запас на то, что русский текст длиннее);
      - перенос: только если `slotY` фиксирован по разметке исходного текста → `budget = haveY`, либо известна `need_preY` → `budget = need_preY × 1,25`;
      - иначе (нет разметки исходного текста) — **ничего не делать**, оставить `cap`. Классификацию «по разметке русского текста» (`Init.lua:3892-3896`) и `parentRoom` для бюджета **не использовать**. Считать `runtimeMetrics.TextFitNoBudget`.
   3. **Правило.** `need ≤ budget + 1` → оставить `cap`. Иначе `size = max(min, floor2(cap × budget / need))`, `min = max(12, 0,6 × авторский)`, но не больше `cap`. Не больше 2 перезамеров, как сейчас (`noeffect`, `fail` → `fit.md`).
   4. **Бюджет времени.** `TextFitMsMax` сейчас 22 мс. Замер только при изменении текста или `cap` (кэш уже есть). Отложенный замер — не больше N виджетов за тик в пределах 2 мс; `ForceLayoutPrepass` вызывать только для виджетов с надёжной меркой, у остальных не звать.
3. **Лимит «Разово».** В `prefixMap` (`Init.lua:2640-2669`) добавить `["Постоянный"]`, `["Постоянно"]`, `["Permanent"]`, `["永久"]` → `"Разово "`. Проверить, что `normalizeShopLotLimit` вызывается для этой карточки: вызовы на `:3226` и `:4765`, Chess Shop.
4. **`EarlyNested` оставить** (с ним вид как в v2.9.6). `NestedEarlyMsMax = 23` мс — записать в `late.md` / ROADMAP как техдолг. Не трогать без данных.
5. **Диагностика и отчёт.** `fit.md`: колонка `mode`, отдельные счётчики `NoBudget`, раздел «уменьшено ниже v2.9.6» (что дал `cap` сверх пороговых размеров). `overflow.csv`: поле `cap`. Сравнение с v2.9.6 по числу переполнений — в `REPORT.md` или в выводе `CollectDiagLogs.ps1`.
6. **Документы.** `DIAGNOSTICS.md` (`TextFit = legacy | cap | measure`, `NoBudget`). `LESSONS.md`: «родитель-авторазмер растёт вместе с текстом, поэтому бюджет по родителю всегда "помещается"; мерка — только разметка исходного текста; потолок — проверенный вид».
