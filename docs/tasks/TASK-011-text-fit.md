## Первопричина 1. Размер задаётся по длине строки, без измерения

### Код
`translateTextWidget` (`Init.lua:3665-3842`) стилизует **каждый** текстовый виджет, через который проходит (панельные обходы `Init.lua:3986`, `4041` и exact-хуки), даже если текст не менялся:
- `getAdjustedFontSize` (`Init.lua:3641-3663`) всегда возвращает `авторский + 2` (при авторском > 36 — 18+2). Размер кэшируется по `GetPathName`.
- Ветка `isTitleName` (`Init.lua:3763-3765`) срабатывает по подстроке в имени виджета: `title`, `btn`, `tab`, `header`, `name`, `sub`, `choice`, `server`, `chapter`, `rank`. Порог по длине: `> 14` символов → `min(base, 14)`, `> 10` → 15, `> 6` → 16, иначе 18 или `base` (`Init.lua:3805-3817`). Кроме того, ветка **выключает авторский перенос** (`SetAutoWrapText(false)`, `Init.lua:3818-3822`).
- Остальные виджеты: при `base > 22` размер 20, иначе `base`, то есть авторский + 2 (`Init.lua:3823-3827`).
- Синергии Автошахмат — свои пороги `> 14` → 10,5, `> 8` → 12 и перенос выключен (`Init.lua:3791-3804`).
- У кириллицы `LetterSpacing` всегда 0, в том числе когда авторский интервал положительный (`Init.lua:3768-3771`, `3785`).
- Те же пороги по длине продублированы в `LoginServerItem` (`Init.lua:8660-8690`) и в Esc-меню (`Init.lua:9646-9652`, `ESC_MENU_LOCKED`; оно проверено пользователем, в этой задаче не трогается).
- Замеров нигде нет: в `Init.lua` нет ни одного вызова `GetDesiredSize`, `ForceLayoutPrepass` или `GetCachedGeometry` для текста (единственный `GetCachedGeometry` в `Init.lua:6126` вызывается для подсказки).

Проверка родителя в диагностике (`AbsruDiagnostics.lua:1066-1093`) сравнивает абсолютные прямоугольники с допуском 1 px и не записывает величину выхода за родителя: колонка `excess` в отчёте считается как `need − have` и для `parent` всегда 0.

### Вывод
Пороги по длине строки дают все три ошибки сразу: лишнее уменьшение, увеличение на +2 без проверки и выключение авторского переноса. Подгонять размер надо по замеру (`GetDesiredSize`) против доступной ширины. Доступная ширина — это собственный слот виджета, если он фиксирован; а если виджет авторазмерный, то ширина до правого края родителя, но не меньше ширины исходного текста. ## Первопричина 2. Задержка перевода — отложенный проход по панели через 0,10 с

### Как устроено
- Хук `UIComponent.Open` / `Refresh` (`Init.lua:10700-10747`) после оригинального метода синхронно вызывает `panelTextRepair:ProcessOnce` (`Init.lua:10739`). Первый проход (`Open`) переводит то, что уже есть в дереве, и ставит в очередь отложенный проход `delayed` через **0,10 с** (`Queue`, `Init.lua:9999`), а для панелей из `extendedPanelRepairDelays` (`Init.lua:9774-9791`) ещё и проходы `extended-<delay>` (`QueueExtended`, `Init.lua:10029-10033`).
- **Вложенные компоненты пропускаются:** если у компонента есть `parentComponent`, `ProcessOnce` возвращает 0 (`Init.lua:9949-9956`, счётчик `NestedComponentSkips`). Элементы списков и подвкладки заполняются после `Open` панели, поэтому их текст до прохода `delayed` через 0,10 с (≈6 кадров) остаётся исходным. Это и есть «исходный текст сменяется через мгновение».
- `NestedComponentSkips` по сессиям: 426, 18906, 2000, 3702, 1363, 964, 4253, 1073, **2381** (v2.9.6). Вложенные компоненты сами вызывают базовые `Open`/`Refresh`, то есть момент, когда их текст уже выставлен, наш хук видит. Просто он ничего не делает.
- Проходы диагностики `PanelWalk` через 0,5 и 2,0 с только наблюдают (DIAGNOSTICS.md), текст они не меняют.

### Шаг 2. Подгонка по измерению (`Init.lua`, `translateTextWidget` и `runtimeFixes.TextFit`)
Режим — константа `TEXT_FIT_MODE = "measure"` внутри блока, по образцу `CYRILLIC_FONT_MODE`. Dev-флаг `TextFit = "legacy"` в `absoluteru_dev.lua` возвращает старые пороги для сравнения на одну версию. Удалить их после подтверждения.
1. **Авторское состояние.** Хранить его в слабой таблице по виджету: `size`, `ls`, `wrap`, `need_pre`. Если игра сама сменила `Font.Size` (текущий размер не равен ни подогнанному, ни авторскому), взять новое значение как авторское. Так обрабатывается случай `Text_ItemName`. `getAdjustedFontSize` (+2) и кэш `widgetOriginalFontSizes` по пути удалить.
2. **Стилизация.**
   - Кириллица: `LetterSpacing = max(0, авторский)` и в виджете, и в `font.LetterSpacing`. Прочий текст — авторский шрифт и интервал (`restoreAuthoredFont`, как сейчас).
   - Размер — авторский, без +2.
   - Авторский `AutoWrapText` не выключать: удалить `SetAutoWrapText(false)` в ветке `isTitleName`, а саму ветку и пороги (`Init.lua:3805-3827`) удалить. У синергий оставить выключенный перенос и `SetRenderScale(0.7)` для `title_fetter`, а пороги длины (`Init.lua:3791-3799`) заменить подгонкой.
3. **Замер.** Замерять только если текст или размер изменились с прошлой подгонки (кэш `fittedText` и `fittedSize`). Иначе ничего не делать: так повторные проходы `delayed` / `extended` не добавляют работы.
   - `have` = `GetLocalSize(GetCachedGeometry())`. Если 0 (виджет ещё не прошёл layout) — отложить (п. 5).
   - `ForceLayoutPrepass()` (если проба доступна), затем `need = GetDesiredSize()`. Если prepass нет — отложенный замер на следующем тике.
   - **Доступная ширина** `budget`:
     - слот фиксирован (`have.X > need_pre.X + 1` или `need_pre` неизвестен и `have.X < need.X`) → `budget = have.X`;
     - авторазмер → `budget = max(need_pre.X, правый край родителя − левый край виджета)` в локальных px (как в диагностике: `LocalToAbsolute` и масштаб). У `ScrollBox` родителя не учитывать.
   - С переносом (`wrap`) сравнивать высоту: `need.Y` против `have.Y`, если высота слота фиксирована.
4. **Правило подгонки.**
   - Если `need.X ≤ budget + 1`, оставить авторский размер.
   - Иначе `size = max(min_size, floor2(size × budget / need.X))`, шаг 0,5. Применить `SetFont`, повторить prepass и замер. Если всё ещё не помещается, сделать ещё один шаг. Итого не больше 2 перезамеров.
   - `min_size = max(12, 0,6 × авторский)`; если авторский меньше 12, то авторский. Нынешние пороги уже опускали 24–27 до 14 (0,52–0,58), и на читаемость пользователь не жаловался.
