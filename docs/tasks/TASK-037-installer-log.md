# TASK-037: журнал установщика в файл и подробности о блоках запуска в кеше

## Симптом (2026-10-17)
У игрока (папка игры `D:\GMZZLauncher\Game\C7`, установщик v3.1.0-RU) в окне видна ошибка:
«Версия игры не поддерживается: найдено 3 подходящих блоков запуска в Saved\kscache\2218968\pakchunk0-Windows.pak».

- Текст формирует `InstallerCore.InspectCache` (`installer/InstallerCore.cs:328-332`, состояние `CacheState.Ambiguous`). Блок считается подходящим, если совпали заголовок (`original_head_hex` или `installed_head_hex`) и sha256 всех 5258 байт (`InstallerCore.cs:314-321`). Значит, в паке игрока лежат 3 **полностью одинаковых** копии блока: чистые, с мостом или вперемешку.
- Проверка манифеста (`InstallerCore.cs:304-310`) у игрока прошла, то есть сборка та же, что у пользователя (2218968, манифест `package_2018737.manifest`).
- На ПК пользователя в том же паке ровно **одна** копия: блок с мостом на смещении 41063360 (скан 2026-10-17; запись `Saved\RussianPatchBackups\cache-launch-2218968.json` с тем же смещением). Размер пака после установки 112 028 892 байта.
- Почему у игрока копий три, не выяснено: в сообщении нет ни смещений, ни типа копий, ни размера пака. Установщик пишет журнал только в окно (`MainWindow.Log`, `installer/Ui/MainWindow.cs:216-225`), файла журнала нет. Лог игры `C7.log` тут бесполезен: ошибка возникает в установщике, до запуска игры.

Гипотезы (не подтверждены, проверить по данным игрока):
1. Лаунчер докачал или обновил пак не так, как у пользователя, и в файле остались «мёртвые» копии файла LaunchInstance (старые записи pak, на которые индекс уже не ссылается).
2. На пак игрока раньше ставили мост другой версией установщика, а потом лаунчер дописал свежие чистые копии.

Исправление самой неоднозначности (например, выбор живой копии по индексу pak) — **отдельная задача** после получения данных. Эта задача только делает так, чтобы следующий такой отчёт содержал всё нужное.

## Связь с TASK-035

## План
1. **Журнал установщика в файл.**
   - Путь: `%LOCALAPPDATA%\AbsoluteRU\installer.log` (`Environment.SpecialFolder.LocalApplicationData`). Папка рядом с exe не подходит: exe часто лежит в «Загрузках», в архиве или только для чтения. Папка игры тоже не подходит: её может не быть или она ещё не выбрана.
   - Новый небольшой класс (например, `installer/InstallerLog.cs`, без WPF): `Append(string line)` дописывает строку `yyyy-MM-dd HH:mm:ss <текст>` в UTF-8 без BOM. При старте установщика, если файл больше 1 МБ, переименовать его в `installer.old.log` (старый `.old` заменить). Первая строка сессии: `=== AbsoluteRU <AppInfo.Version> запущен ===`. Все ошибки записи глотать: журнал в файл не должен ронять установщик.
   - `MainWindow.Log` (`MainWindow.cs:216`) вызывает `InstallerLog.Append` для каждой строки, вместе с выводом в окно. CLI-режимы (`PatcherBackend.DiagnosePath`, `RunCliInstall`) тоже пишут туда же.
   - Новый `.cs` добавить в списки исходников `installer/build_installer.ps1:26` и `tools/BuildTools.ps1:21`.
2. **Подробности о кандидатах в `InspectCache`** (`InstallerCore.cs:284-339`):
   - В `CacheInfo` (`InstallerCore.cs:61-68`) добавить `long PakSize` и список кандидатов `List<CacheHit> Hits`, где `CacheHit { long Offset; string Kind; }`, `Kind` — `"чистый"`, `"мост"` или `"заголовок совпал, sha нет"` (для попаданий из `FindAll`, у которых sha256 не совпал).
   - Для `NotFound` и `Ambiguous` к `Detail` дописывать: размер пака в байтах и до 10 кандидатов, например `(размер пака 112028892; кандидаты: 41063360 мост, 98765432 чистый, …)`. Так одного скриншота окна хватит для разбора.
   - `PatcherBackend.DiagnosePath` (`PatcherBackend.cs:401-403`) выводит то же самое.
3. **Запись проверки папки в журнал.** Сейчас результат проверки (`MainWindow.cs:320` и соседние ветки) показывается только красной строкой под полем папки, в журнал не попадает. При состояниях кеша `UnsupportedBuild`, `NotFound` и `Ambiguous` один раз на каждую проверку папки писать в журнал строку `Проверка кеша: <State>, версия <Version>, <Detail>`, а также содержимое `Saved\kscache\AssetsVersion.txt`. Не повторять одну и ту же строку на каждый тик `pathTimer`: писать, только если текст изменился с прошлой проверки.
4. **TASK-035, `LogCollector`:** копировать `installer.log` и `installer.old.log` (если есть) в папку с логами, а в `info.txt` в раздел «Версия игры» добавить `Hits` и `PakSize` из `InspectCache`.
5. **Тесты `tools/InstallerCoreTests.cs`:**
   - `InspectCache` на поддельной папке в `temp/installer-tests/…`: пак с двумя одинаковыми чистыми копиями блока → `Ambiguous`, в `Hits` два элемента `"чистый"` с правильными смещениями, в `Detail` есть оба смещения и размер пака. Посмотреть, как существующие тесты кеша собирают поддельный пак и манифест, и сделать так же.
   - `InstallerLog`: запись в файл во временной папке (путь сделать параметром или внутренним свойством для теста), ротация при размере больше 1 МБ.
6. Собрать `tools/BuildTools.ps1`, прогнать `tools/InstallerCoreTests.exe`. Все тесты должны пройти.
7. `docs/PROJECT_MAP.md`: упомянуть `installer.log` и его путь. `docs/DIAGNOSTICS.md`: добавить раздел «Журнал установщика» (где лежит, что в нём искать).
8. Коммит `feat(installer): TASK-037 installer log file, cache candidates detail`. Релиз собирать только по просьбе пользователя.
