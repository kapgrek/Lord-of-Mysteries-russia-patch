# TASK-045: свой мост без CPDD — разведка

## Симптом
Обновление игры 2307645 (TASK-044) сломало мост: перевод не загружается. Пользователь сообщает, что английский патч CPDD, вероятно, больше не будет обновляться. В репозитории `Lani27/lord-of-mysteries-english-patch` последний push 24.10 (v2.7.5), объявлений нет, но и архивом он не помечен. Без CPDD нужен свой мост под каждое крупное обновление.

## Первопричина
См. TASK-044: новый базовый `pakchunk0-Windows.pak` (sha `7791a5fb…`, 443251659 байт) больше не содержит чистый блок запуска `566e72d6…`, под который собран `bridge/LaunchInstance.native-bridge.padded.oodle`. Сами мы мост собрать не могли из-за Oodle (`TASK-032…md:69`).

Что известно о блоке:
- Чистый блок базового пака (4660 байт) — `Saved/RussianPatchBackups/launch-original.block` в игре. Мост CPDD для него — `patch_payload/bridge/LaunchInstance.native-bridge.padded.oodle` (те же 4660 байт, «padded»).
- Пара для кеша: `RussianPatchBackups/cache-launch-2218968.block` (5258, `3124ee28…`) и `patch_payload/bridge/cache-startup.oodle` (5258, `ee48b48a…`).
- Начало блоков (`supported_game.json:26-27`): `8c060014…1b4c4a82…`. Это заголовок куска Oodle Kraken, а внутри — байткод LuaJIT с нестандартной версией `0x82` (собственная сборка игры). У стандартного LuaJIT 2.x версия `0x02`. Компаньоны CPDD `.compat.luac` с тем же заголовком считались «зашифрованными» (память проекта), но это не проверено.

## План (разведка, ничего в игру не пишем)
Цель — ответить на три вопроса и оценить, сможем ли мы собирать мост сами.

1. **Распаковка.** Скопировать оба `.block` из `RussianPatchBackups` в `reference/bridge_re/blocks/` (только чтение из игры). Распаковать 4 блока: 2 чистых и 2 моста CPDD.
   - Итог: распакованные `*.luabc` и их размеры. Проверить, есть ли в `ooz` **упаковщик** Kraken: от этого зависит обратная сборка.

   - Если отличаются несколько инструкций и константа, патч механический: описать его как алгоритм.

Если упаковщика нет, проверить вариант «несжатый кусок Kraken», то есть влезает ли он по размеру. Проверяется ли хеш записи в индексе пака (у CPDD работает, значит, скорее всего, нет; проверить по полям записи).

## Результат (2026-11-13, частичный: шаг 3 выполнен, шаги 1, 2 и 4 ждут `ooz`)

### Главное: новый базовый пак содержит чистый кешевый блок, под который у нас уже есть мост CPDD
- В новом `Content/Paks/pakchunk0-Windows.pak` (443251659 байт, sha `7791a5fb…`) по смещению **422563913** лежит кусок Kraken размером **5258** байт с sha256 **`3124ee28ea3b4db83666da313d5e022eaef882d191356d5e38b86d94c6173084`**. Это побайтно `RussianPatchBackups/cache-launch-2218968.block`, то есть `cache_launch.clean_sha256` (`installer/supported_game.json:23`). После него идут нули (выравнивание).
- Обновление 2307645 вшило в базовый пак тот `LaunchInstance`, который раньше приходил хотпатчем 2218968. Мост CPDD для этого блока у нас уже есть: `patch_payload/bridge/cache-startup.oodle` (5258 байт, sha `ee48b48a…`, `supported_game.json:24-25`). **Значит, TASK-044 решается без нового релиза CPDD и без своей сборки моста:** писать `cache-startup.oodle` в базовый пак по смещению 422563913.
- sha пака после такой записи (посчитано в памяти потоком, на диск ничего не писали): **`21bc7187494faaba8888f5858f62eba94606e125311620736950f1556c0f04bc`**, размер не меняется. Контроль: та же процедура с чистым блоком дала исходный `7791a5fb…`.
- Кеш на ПК пользователя: из `pakchunk0` остался только `kscache/2307645/pakchunk0-Windows.pak` (22227 байт). В нём один Lua-кусок с именем другой длины (`0x3e`), блока запуска нет. Кеш `LaunchInstance` не переопределяет. Другие папки `kscache/*` пакетов `pakchunk0*.pak` не содержат.

### Шаг 3 подробно
- Футер UE есть (магия `E1 12 6F 5A` за 204 байта до конца, версия `0x8000000C`, флаг шифрования индекса `01`, метод `Oodle`). Поля `indexOffset/indexSize` выглядят как мусор (`0x69A7CE6146AB5209…`), значит, футер обфусцирован вместе с индексом. По индексу запись не найти, поэтому проверить, хранится ли в записи хеш блока, нельзя. Косвенный ответ: мост CPDD меньше чистого блока и добит нулями, и это работало, значит, хеш блока не проверяется.
- Поиск без индекса: заголовок Kraken `8C 06`, а через 5–10 байт магия LuaJIT `1B 4C 4A 82` (первые 8 байт вывода Kraken хранит как есть). Нашлось 40 004 Lua-куска. Байт после `1B 4C 4A 82 08` — длина имени чанка. У блока запуска она `0x36` (54), таких кусков 8, все в районе 422–423 МБ (вероятно, `Launch/Base/*`). Совпадение по sha только одно.
- Сдвиг относительно старого базового пака: 427225161 → 422563913 (−4 661 248).
- Разбор заголовка куска по формату Kraken: `8C` — новый формат, restart, без checksum; `06` — Kraken; следующие 3 байта — `compressed_size − 1` (у чистого старого базового блока `0x122E` → 4655 + 5 = 4660; у моста `LaunchInstance.native-bridge` `0x121E` → 4639 + 5 = 4644, то есть 16 байт добивки; у кешевого чистого `0x1484` → 5258, у `cache-startup.oodle` `0x146F` → 5237, добивка 21 байт).

### Шаги 1, 2, 4: что мешает
- Компилятора C++ нет (нет `cl`, `gcc`, `clang`, MSBuild, VS). Есть только `csc` .NET Framework 4.0 (C# 5) и рантайм `dotnet` без SDK. Oodle в игре вшит в `C7-Win64-Shipping.exe` статически, `oo2core*.dll` нет ни в игре, ни в других установленных играх.
- Чтобы распаковать блоки, нужно скачать исходники `ooz` и либо портировать декодер Kraken на C# 5, либо поставить переносимый компилятор (например, llvm-mingw). Скачивание не выполнялось: нужно подтверждение в чате.
- Для обратной упаковки упаковщик Kraken не обязателен: декодер принимает потоки типа 0 (raw), поэтому достаточно своего простого LZ-кодера с raw-потоками литералов, токенов и смещений. Влезет ли результат в 5258 байт, можно сказать только после распаковки (нужен размер байткода).
