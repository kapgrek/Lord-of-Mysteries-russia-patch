# TASK-016: Автошахматы — подсказки синергий и фигур не помещаются, «3 шт.» вместо цифр

Дорожная карта: [ROADMAP.md](ROADMAP.md). Предыдущие: [TASK-013](TASK-013-text-fit-cap.md) (подгонка `legacy` / `cap`), [TASK-014](TASK-014-autochess-gaps.md). Данные: `reference/logs/2026-09-25_*` (overflow / untranslated / fonts), скриншоты пользователя 2026-09-26 (v3.0.0-RU).

Статус: **анализ завершён**, ждёт чата исполнения. Версия — **v3.0.1-RU** (правило нумерации в ROADMAP).

## Симптомы (v3.0.0-RU, 2026-09-26)
1. **Подсказка синергии** («Потусторонний мир»): окно сильно растянуто в ширину. Внизу строка «Дважды щелкните портрет произведения, чтобы отметить его как рекомендованный.» в одну строку и крупным шрифтом — она задаёт ширину всего окна. В кружках уровней видно «3 шт», «5 шт» вместо «3», «5» (текст вылезает из кружка).
2. **Подсказка фигуры** (например, «Старик Нил»): описание навыка («Ритуал трех свечей → Произносит заклинание и запускает серию трёх…») крупное и обрезается: видно ~2 строки. По словам пользователя, так почти у всех фигур. Рядом в шапке «3 плиток» (дальность) и «3 шт.» (стоимость) налезают на роль «Поддержка дальнего боя».

## Первопричины

### A. Голые числа переводятся как «N шт.» (ShardCompiler)
- В батчах есть записи вида `source_cn: "3个"`, `ref_en: "3"`, `target_ru: "3 шт."`: `batch_010.json` id 047789 («3»), `batch_023.json` id 114802 («4»), `batch_025.json` id 120779 («1»), `batch_026.json` id 126093 («5»), `batch_004.json` id 018072 («2个» / «2 items»).
- `tools/ShardCompiler.cs:94-109` кладёт в шарды и английский ключ `ref_en → target_ru` без проверки. В сгенерированных шардах: `RuntimeTextGemini_0d0.lua:273 ["1"] = "1 шт."`, `_0d8.lua:173 ["3"] = "3 шт."`, `_0c4.lua:243 ["4"] = "4 шт."`, `_0c0.lua:262 ["5"] = "5 шт."`.
- Рантайм (`Init.lua:3307`, `lookupGeminiTextFuzzy(value)` в `translateVisibleText`) находит любую строку-число «1», «3», «4», «5» и заменяет на «N шт.».
- Подтверждение в overflow-логах (`reference/logs/*/Saved/Mods/logs/*overflow*.jsonl`), панель `AutoChess_Hud_Panel`: `WBP_AutoChess_HUD_Fetter_Item/Text_Lev` «1 шт.» (58 раз, need 66,7 при have 16), `WBP_AutoChess_Progress/Text_CountDown` «1 шт.» (таймер!), `WBP_AutoChess_SoldBtnLeft/Text_CoinNum` «1 шт.», `WBP_AutoChess_HUD_ShopBtn/Text_Num` «3 шт.», `WBP_AutoChess_HUD_UpgradeBtn/Text_Level` «3 шт.», `WBP_AutoChess_Tips_Property_Item_6/Text_Property` «4 шт.» (275 раз). Семёрка не страдает (ключа «7» нет) — это и видно на скриншоте 1 («3 шт», «5 шт», «7»).
- Там же без букв: даты (`["2025/07/30"] = "30 июля 2025 г."`, `_252.lua:8`) и суммы (`["122,000"] = "122 000"`). Английский ключ без букв не несёт смысла и не должен переводиться по `ref_en`.

### B. Строка-подсказка внизу подсказки синергии
- Батч: `batch_012.json:10584`, id **056763**, `双击棋子头像可标记为推荐` (12 иероглифов) → «Дважды щелкните портрет **произведения**, …» (76 символов). «Произведения» — ошибка перевода: 棋子 здесь «фигура».
- Виджет без переноса (одна строка), стилизуется порогами `TF.Legacy` (`Init.lua:4131-4178`: авторский + 2, без уменьшения для обычного текста). Окно подсказки авторазмерное и растягивается под эту строку.
- Имя виджета в логах не найдено: `fonts.json` пишет только Title-шрифт (из `WBP_AutoChess_Tips_FetterTips` там только `Text_Title`), overflow по FetterTips пуст. Поэтому искать виджет **по тексту**, а имя записать в диагностику.

### C. Описание навыка в подсказке фигуры обрезается
- Виджет: `WBP_AutoChess_Tips_PieceTips/RichTextBlock_Detailed` (**RichTextBlock**), заполняется в `AutoChess_Tips_PieceTips.Refresh` (scope `ac-class:AutoChess_Tips_PieceTips.Refresh` в untranslated-логах).
- Overflow-логи (даже для английского текста): need Y **120–160** при have Y **83–96**, родитель `KGVerticalBox` высотой 121, ширина 318–510. Русский текст длиннее — переполнение сильнее.
- `SetFont` для RichTextBlock не работает и запрещён (`Init.lua:4378-4381`: `DefaultTextStyleOverride` ломает материалы, фиолетовый текст). Рабочий приём для RichText уже есть в проекте: `SetRenderScale` с пивотом у левого края (`Init.lua:7651-7666`, `fitSequencePromotionChangeText`).

### D. «%d плиток» (дальность) в шапке фигуры — попутно
- `batch_020.json:8196`, `%d格` → «%d плиток» (EN «%d tiles»). По-русски «3 плиток» ещё и неграмотно. В шапке рядом со значком скрещённых мечей лучше коротко.

## План
Новых локальных переменных верхнего уровня в `Init.lua` не добавлять (VerifyPatch). Lua — UTF-8 без BOM, LF.

1. **ShardCompiler: без английских ключей без букв** (`tools/ShardCompiler.cs:96`). Английский ключ `ref_en → target_ru` добавлять, только если в `en` есть хотя бы одна буква (`char.IsLetter`). Китайский ключ не трогать. Пересобрать `ShardCompiler.exe` (`tools/BuildTools.ps1`), перегенерировать шарды, убедиться, что в `RuntimeTextGemini_*.lua` нет ключей `["1"]`, `["3"]`, `["4"]`, `["5"]` и прочих из цифр и знаков (проверочный grep `^\s*\["[0-9%\s/+\-.,:]*"\]\s*=` → только записи, пришедшие из `source_cn`, если такие есть). Вывести в лог компилятора число пропущенных ключей.
   - Страховка в рантайме: в `translateVisibleText` перед `lookupGeminiTextFuzzy` (`Init.lua:3307`) строку без букв (только цифры, пробелы, `%/:.,+-`) не искать в шардах. Проверить, что нормализация больших чисел (`normalizeLocalizedLargeNumbers`, `:3316`) идёт как раньше.
2. **Строка 056763.** В `batch_012.json` id 056763: `target_ru` → «Дважды щёлкните по портрету фигуры, для сохранения в рекомендованные.» (смысл 双击棋子头像可标记为推荐; «фигура» — по глоссарию Автошахмат). Хук Stop перекомпилирует батч.
3. **Уменьшить эту строку в 2 раза.** В `translateTextWidget` (`Init.lua:4306+`), после выбора размера (`TF.Legacy` / `TF.Cap`, до `SetFont` на `:4375`): если итоговый текст виджета — перевод 056763 (сравнивать с `target_ru` из шарда по ключу `双击棋子头像可标记为推荐`, а также с EN «Double-click a piece's portrait to Mark it as recommended» и CN-исходником на случай непереведённого), то `font.Size = max(10, floor(size × 0.5))`, перенос не включать. Таблицу «текст → множитель» держать полем `runtimeFixes.TextFit` (не новой локальной). В `DiagnosticsMode` — одна строка на сессию: `autochess tip hint shrink widget=<имя> panel=<панель> size=<до>-><после>`, чтобы узнать имя виджета.
4. **Описание навыка фигуры** (`RichTextBlock_Detailed` в `AutoChess_Tips_PieceTips`):
   1. В `hookAutoChessClassTable` (`Init.lua:11021-11022`) для класса `AutoChess_Tips_PieceTips` и методов `Refresh` / `OnRefresh` передать `afterTranslate` = новая `runtimeFixes.fitAutoChessPieceSkill(comp)` (вместо `nil`).
   2. `fitAutoChessPieceSkill`: найти `RichTextBlock_Detailed` (`getNamedWidget(comp.view, …)` / `userWidget`), сбросить `RenderScale` в 1, получить `have` (кэшированная геометрия виджета; если слот авторазмерный — высота родителя `KGVerticalBox` минус высота строки названия навыка) и `need` через `ForceLayoutPrepass` + `GetDesiredSize` (экспортировать `measure` из `runtimeFixes.TextFit` как `TF.Measure`, не дублировать).
   3. Если `needY ≤ haveY + 1` — ничего. Иначе подобрать масштаб `s` из ряда 0,9 / 0,8 / 0,72 / 0,65 / 0,6: для каждого `SetWrapTextAt(haveX / s)` (перенос по более широкой строке, чтобы после сжатия текст занял ширину блока) и перемерить; взять первый `s`, при котором `needY × s ≤ haveY`. Применить `SetRenderTransformPivot(0, 0)`, `SetRenderScale(s, s)`. Минимум 0,6; если и его мало — оставить 0,6.
   4. Если геометрии ещё нет (первое открытие) — отложить на 1 тик через существующую отложенную очередь `TextFit` или `AddTimerWithFunction`, как `scheduleWidgetProbe` (`Init.lua:4438`). Не больше одного замера на пару (виджет, текст): кэшировать `s` по тексту.
   5. Если `SetWrapTextAt` у RichTextBlock нет (проверить через `pcall`) — масштаб без изменения переноса, `s = max(0,6, haveY / needY)`, и записать `api WrapTextAt=missing` в диагностику.
   6. Диагностика в `DiagnosticsMode`: `autochess piece skill fit need=<X>x<Y> have=<X>x<Y> scale=<s> wrapAt=<…>` (первые 5 раз за сессию).
5. **«%d плиток»** (`batch_020.json` id `%d格`): `target_ru` → «%d кл.» Перед правкой grep по коду/логам, где ещё встречается `%d格` / «tiles» (если только Автошахматы — менять).
6. **Версия и документы.** v3.0.1-RU во всех местах из правила ROADMAP. `LESSONS.md`: «ShardCompiler клал `ref_en` без букв (“3”) как ключ перевода → все голые числа в UI становились “3 шт.”; английский ключ — только с буквами». ROADMAP — строка TASK-016. `TRANSLATION_GUIDE.md`: у записей с чисто числовым `ref_en` английский ключ не создаётся. Закоммитить, запушить; релиз публиковать только по решению пользователя.
