# TASK-021: «Скачки» размера текста в настройках и карточках Автошахмат (TextFit `legacy`)

Предыдущая: [TASK-020](TASK-020-autochess-cards-traintrade.md), пробы настроек — TASK-019 R0.2–R0.3. Статус: **анализ 2026-09-27, ждёт исполнения.**

## Симптом
Проверка пользователя на v3.0.5-RU (сессия `20260927-042955`, слот s3, логи `reference/logs/2026-09-27_0436/`, в C7.log `v3.0.5-RU active`): «настройки так же скачут, как раньше; скачут и карточки в шахматах». Текст появляется одним размером и через мгновение меняет его.

## Данные
- `report/late.md`: `panel:Settings_Panel:delayed` — `text_changes 0`, `style_changes 10`; `panel:AutoChess_CardDescription_Panel:delayed` — 56 проходов, `text_changes 0`, `style_changes 44`. Отложенный проход текст не меняет, а меняет размер — это и есть видимый скачок.
- `absru-s3-fit-*.jsonl`, `kind = "style"`: 1700 строк (вниз 1068, вверх 632).
  - Настройки: 10 строк `Text` в `Settings_Switch_Item` («Блокировка предмета», «Торговый замок», …) `22.5 → 20`, reason `owner:Settings_Panel/Settings_Switch_Item:delayed`. При `Open` этих строк нет: пункты заполняются после `Open`, оформляем их только отложенным проходом.
  - Карточки: `Text_Lev «1»` **чередует** `20 → 22` и `22 → 20` на проходах `…:delayed` / `…:extended-1.5` (31 строка). Это цифра, не кириллица.
  - Прочее без кириллицы с +2: `TB_Num «00%» 24→20`, `Text_CD_lua «6» 14→16`, `KText_Progress_lua «0» 21→20`, `Text_Level «» 24→20`.
  - `Text_ChessName` в карточке меняет размер от имени к имени (`«Трисси» 14→18`, `«Гигантский труп» 18→14`): пороги длины `isTitleName` в `legacy`, reason `ac-class:AutoChess_CardDescription_Panel.OnRefresh` — в том же кадре, что и SetText игры.
- Проба таймлайна настроек (`probes.settings`, TASK-019 R0.3) **не дала данных**: 20 записей в одну секунду, `refreshes = 0`, `classes = {}`.

## Первопричины
1. **`TF.Legacy` не идемпотентен** (`Init.lua` ~4334–4381). Размер = `st.size + 2` (для не-заголовков, потолок 20 при `base > 22`), где `st.size` — «авторский» размер, снятый `TF.State` (~3974) с **текущего** шрифта при первом обращении к виджету; состояние лежит в `states` со слабыми ключами по Lua-объекту виджета. Если состояние создаётся заново (новый прокси того же UObject или сборка мусора), авторским считается уже увеличенный размер: 20 → 22, затем «авторский» 22 → `base 24 > 22` → 20, затем снова 22. Строки `Text_Lev 22→20` на отложенных проходах возможны только так: при устойчивом `st.size = 20` `legacy` всегда даёт 22.
2. **`legacy` оформляет и текст без кириллицы** (`Init.lua` ~4756–4766: `TF.Legacy` вызывается при любом `hasCyrillic`; кириллица влияет только на межбуквенный интервал). Для цифр и латиницы +2 ничего не даёт, а каждый проход игры, возвращающий авторский размер, даёт скачок.
3. **Пункты настроек оформляются поздно.** Текст `Settings_Switch_Item` игра ставит после `Open` (уже русский из StringDB, `text_changes = 0`), наш первый проход по нему — `delayed`. Классового хука на `Settings_Switch_Item` нет (`runtimeFixes.LateLabelClasses` ~11690 и `Settings_Option_Item.Refresh` ~9540 его не покрывают).
4. **Проба R0.3 сломана:** `D.ProbeSettingsHooks` (`AbsruDiagnostics.lua` ~1104) узнаёт панель по `componentUid(component) == "Settings_Panel"`, а `componentUid` (~429) берёт `component.uid` — у дочерних компонентов панели он тоже `Settings_Panel`. Каждый дочерний `Open` создаёт новую запись и сбрасывает `S.settingsCur`, лимит 20 исчерпан на первом открытии.

## План
1. **Идемпотентность `legacy`:** авторский размер хранить по устойчивому ключу (`widget:GetPathName()`, кэш с лимитом) и не принимать за авторский размер, который мы сами поставили (`st.applied` / реестр путь → применённый размер): если при создании состояния текущий размер равен ранее применённому для этого пути — брать сохранённый авторский. Диагностика (только при Diag): счётчик `TextFitStateRecaptured` и строка `fit kind="recapture"`.
2. **Без кириллицы — авторский размер:** в ветке `legacy`/`cap` при `not hasCyrillic` не вызывать `TF.Legacy`, а вернуть `st.size` (как делает ветка `measure`, ~4791). Исключение не нужно: +2 вводился ради кириллицы (v2.9.6).
3. **Настройки — оформлять в момент заполнения:** классовый хук на `Settings_Switch_Item` и `Settings_DoubleSwitch_Item` (по образцу `LateLabelClasses`, методы `^Refresh|^OnRefresh|^Set`, путь `Text`, для DoubleSwitch ещё `Text_Off`/`Text_On`), чтобы отложенный проход находил уже оформленный текст (`style_changes` в `delayed` → 0). Имена методов проверить пробой из п. 4; хук ставить на классы, а не на базу (LESSONS: хуки классов).
4. **Починить пробу R0.3:** панель узнавать по `component.__cname == "Settings_Panel"` (или `uid == __cname`), дочерние `Open` не создают записей. Мок-тест в `temp/t019/test_r0.lua`: панель + 30 дочерних `Open` с тем же `uid` → одна запись.
5. **Не трогать:** пороги длины для заголовков (`Text_ChessName` 14–18 по длине имени) — меняют размер между разными карточками, но в кадре SetText; если пользователь сочтёт это скачком — отдельной задачей.
6. Версия v3.0.6-RU, `PackageRelease.ps1` без публикации.

## Проверка
- Автоматическая: мок на Lua 5.4 (`temp/t019/test_r4.lua` + новые кейсы): (а) виджет 20 → `legacy` 22 → новое состояние для того же пути → остаётся 22 (не 20); (б) текст «1» / «00%» — размер авторский, `SetFont` не меняет размер; (в) `Settings_Switch_Item.Refresh` со строкой «Торговый замок» → размер 20 сразу после `Refresh`; (г) проба R0.3 — одна запись на открытие. `VerifyPatch.ps1`.
- По логам следующей сессии: в `late.md` `Settings_Panel:delayed` и `AutoChess_CardDescription_Panel:delayed` — `style_changes = 0`; в `fit.md` нет чередования `20↔22` у одного пути; `probes.settings[]` — по записи на открытие, `refreshes > 0`.
- В игре (ставить `build\install-local-build.cmd`, в C7.log `v3.0.6-RU active`): открыть настройки 2–3 раза, переключить вкладки — подписи не меняют размер после появления; открыть 5–6 карточек фигур — уровень, числа и описание не «прыгают».
