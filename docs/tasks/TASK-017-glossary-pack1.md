## Симптом
Одна и та же боевая характеристика в интерфейсе, подсказках навыков и снаряжении называется по-разному: 穿刺 — «прокол», «прокалывание», «проникающая способность», «пронзание», «пробивание»; 破防 — «пробитие защиты», «взлом магической защиты», «пробивание брони»; 专攻 — «мастерство», «особая атака», «фокус монстра». Часть строк — машинный перевод без смысла (`batch_005:021226`: «Врата Увеличение блокировки», «Подавление — увеличивается необыкновенными людьми»).

## Первопричина
1. Батчи переводились в разное время разными движками (Google/DeepL через `AutoTranslate.ps1`, ИИ-чаты) без общей проверки терминов. Глоссарий (`source/glossary/*.json`, ~70 записей) боевых характеристик не содержит, а инструмента, который сверяет `target_ru` с глоссарием, нет.
2. Термины живут в четырёх местах: батчи, `source/glossary/*.json` + `docs/GLOSSARY.md`, `tools/ShardCompiler.cs:108-340` (`explicitAliases`), `Init.lua` (ниже). Правка в одном месте не доходит до остальных.
3. В коде уже есть ошибки по этим терминам (`patch_payload/Saved/Mods/lua/mods/cpdd_runtime_fixes/Init.lua`):
   - `:115`, `:165`, `:1130-1135` — `破防提高80` переведено «Пробивание брони увеличено» (破防 — пробой **защиты**, «пробивание брони» — это 破甲);
   - `:2702` — Super Armor = «Неудержимость», в батчах 86 строк «Суперброня».

## План
1. **Глоссарий как данные.** Новый `source/glossary/combat_stats.json` (UTF-8 без BOM, LF). Формат записи:
   ```json
   { "cn": "穿刺", "en": "Piercing", "ru": "Пронзание", "ru_short": "Пронз.",
     "ru_match": "пронза", "forbidden": ["прокол", "прокалыван", "проникающ", "пробити", "пробивани", "пирсинг"],
     "cn_exclude": [], "note": "характеристика; «пробивание брони» — это 破甲" }
   ```
   Для 穿刺 запрет `пробивани` не срабатывает, если в той же строке есть 破甲 (там «пробивание брони» — канон).
   `ru_match` — регулярка по основе с допуском слова между (`снижени\w*(\s+\S+)?\s+урон`), чтобы «снижение получаемого урона» считалось каноном. Записи: семь терминов таблицы + подтермины 物理/魔法/特殊 (Физ./Маг./Особ. …) + `破防条` / `破防状态` («шкала прорыва защиты» / «прорыв защиты» у монстра) + 破甲 «Пробивание брони» (запрещены «разрушение брони», «пробитие брони», «взлом брони»). `cn_exclude` для 破防: `打破防`. Служебные ключи (`_数值`, `_百分比`, `_值`, латиница с `_`) — корзина `S`, не правятся.
   В этот же шаг: `characters_and_factions.json` 黑夜女神教会 → «Церковь Богини Вечной Ночи»; `terms_and_items.json` 非凡特性 → «Потусторонняя характеристика», 扮演法 → «Метод отыгрыша»; Hornacis → «Хорнакис» там, где он есть. Пересобрать `docs/GLOSSARY.md` из JSON (раздел «Боевые характеристики» + ссылка на канон Цитруса).
2. **`tools/GlossaryCheck.ps1`** (UTF-8 с BOM; без ИИ):
   - `-Report [-Terms 穿刺,破防]` — таблица как выше по всем батчам + `temp/glossary_report.md` со списком строк по корзинам;
   - `-FixShort` — корзина `A`: заменить `target_ru` на канон (`ru`, или `ru_short`, если исходный перевод был сокращён), только если `target_ru` целиком — известный вариант или пустой; иначе строка переходит в `B`. Печатать «было → стало»;
   - `-Export -Count 50` — корзины `B`+`C` чанками в `temp/glossary_chunk_NNN.json`: `[{ "key": "batch_005:020853", "source_cn", "ref_en", "target_ru", "terms": [{cn, ru, forbidden}] }]` — в чанк кладутся только термины, найденные в этой строке;
   - `-Import <файл>` — ответ `{ "batch_005:020853": "новый target_ru" }`: запись по файлу и id (UTF-8 без BOM, LF, как `BatchHelper`), отказ строки, если после правки канона нет, изменилось число `%s`/`{0}`/тегов или строка стала пустой. Итог: принято / отклонено со списком.
3. **Субагент `.claude/agents/ru-translator.md`**: `model: sonnet`, инструменты только `Read`, `Write`. Вход — путь к чанку, выход — `temp/glossary_answer_NNN.json`. Правила в теле агента: канон из `terms` строки; **минимальная правка** — заменить термин с согласованием падежа, остальное предложение не трогать, **кроме** явного машинного мусора (бессмыслица, «Увеличится*.1f», английский в `target_ru`) — такую строку перевести заново по `source_cn`; теги, `%s`, `{0}`, `*d`, `{*d,F…}`, `\n` символ-в-символ (выдержка из `TRANSLATION_GUIDE.md` §1–5); строка, где термин — ложное совпадение, возвращается без изменений.
4. **Скиллы** `.claude/skills/glossary-check/SKILL.md` (Report → FixShort → сводка) и `.claude/skills/translate-chunk/SKILL.md` (Export → по субагенту на чанк, до 4 параллельно → Import → `VerifyBatch.ps1` по затронутым батчам → при отказах вывести список). Описание в `TRANSLATION_GUIDE.md` §7.
5. **Прогон пачки 1:** `-Report` (сохранить «было») → `-FixShort` → `-Export` (≈8 чанков) → `/translate-chunk` → `-Report` (цель: `B` = 0, в `C` только ложные совпадения и `S`). Выборку «было → стало» (20 строк, по 3 на термин) записать в раздел «Исполнение».
6. **Код.** `Init.lua:165`, `:1130-1135` → «Прорыв защиты увеличен на <Mark>80</>…» (сверить весь текст с `source_cn` в `:1130`); `Init.lua:115` («Пробивание брони» по хешу) — найти исходник строки: если это 破甲, оставить, если 破防 — «Прорыв защиты»; `:2702` и остальные шаблоны Автошахмат (`:2669+`) — grep по «Неудержим», «прокол», «пробивани» (без «брони»), «пробитие защиты», «Специализация»/«мастерство» → канон. `ShardCompiler.cs:108-340` — grep тех же вариантов, правка на канон (перенос `explicitAliases` в батч — не в этой задаче).
7. **Магазин Автошахмат** (`batch_031:132472`, `:132479`) — по ответу на вопрос 2 (по умолчанию «Шахматная лавка»).
8. **Сборка и документы.** `ShardCompiler.exe`, `VerifyBatch.ps1` (все изменённые батчи — без ERR), `VerifyPatch.ps1`. Версия **v3.0.2-RU** во всех местах из правила ROADMAP. `ROADMAP.md` — строка этапа 7: «TASK-017 (пачка 1) исполнен, ждёт проверки»; `TASK-012` — ответы на вопросы 1–4 со ссылкой сюда; `LESSONS.md` — «термины сверять скриптом по глоссарию; машинный перевод давал 5–6 вариантов одной характеристики, а `伤害加深` — с обратным смыслом».
