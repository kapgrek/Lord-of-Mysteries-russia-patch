### 4. Шрифт
Анализ: [TASK-006-font.md](TASK-006-font.md). Title рисует кириллицу китайским FZ Old Mincho (1,0 em), Regular — Source Han Sans (0,62 em).
- **4a (TASK-006, v2.9.2) — исполнено, ждёт проверки в игре.** `Init.lua`: фиксированные `StandardFontObject` (`Font_Aleo`) и `CinematicFontObject` (`Font_Mistery`) вместо эвристик; `LetterSpacing` у кириллицы 0 (−120/−60 удалены); не-Aleo шрифты с кириллицей → `Font_Aleo` с настоящим typeface. Режим кириллицы — константа `CYRILLIC_FONT_MODE` (релиз: `"typeface"`, Title → Regular) или флаг `CyrillicFont` в `absoluteru_dev.lua`: `"subfont"` дописывает в `Font_Aleo.CompositeFont.SubTypefaces` диапазон U+0400–U+045F (+U+2116) с первым face из `CyrillicFaceCandidates`, проверяет запись чтением, вызывает `FlushFontCache` и при любой ошибке откатывается в `"typeface"`. Диагностика: `fonts.json → composite`, `cyrillic_font`. После подтверждения `"subfont"` в игре — переключить константу одной строкой.
- **4a, продолжение (TASK-007, v2.9.3) — шаги 1–3, 5–7 исполнены, ждут сессии в игре.** Проверка v2.9.2 показала: `typeface` меняет Title → Regular только у виджетов, прошедших через `translateTextWidget`; текст из данных и RichText остаётся Mincho. `subfont` в v2.9.2, вероятно, откатывается: `FInt32Range` через slua не читается. v2.9.3 добавляет строки `cyrillic font mode=` и `[AbsruDiag] session=` в `after_main`, диагностику `title_cyrillic`, пробу `FInt32Range` и покрытия U+0410 каждым SubTypeface (кандидат для Title — `Fallback/NotoSerif_Regular`), подпись «Турнир» в Esc-меню. Сессия A (`reference/logs/2026-09-25_1046`) показала, что `FInt32Range` в slua непрозрачен, поэтому шаг 4 (правка `subfont`) заменён TASK-008.
- **4a, продолжение (TASK-008, v2.9.4) — шаги 1–5 исполнены, ждут проверки в игре.** Новый режим `CyrillicFont = "cultures"` (только по dev-флагу): существующему SubTypeface `Font_Aleo` с face `Fallback/NotoSerif_Regular` (запасной `NotoSans_Regular`, флаг `CyrillicCultureSub`) ставится `Cultures` = текущая культура, чтобы его диапазоны стали приоритетнее default-typeface; проверка чтением, `FlushFontCache`, при ошибке откат в `typeface`; Title → Regular в этом режиме не делается. Проба ключей `.get`/`.set` у `FInt32Range` (только чтение); маркер `[AbsruDiag] session=` перенесён в хук `after_main` с приоритетом 1501 (до `performance-mode`). Если `cultures` подтвердится, переключить `CYRILLIC_FONT_MODE` одной строкой; `subfont` тогда не нужен. **Проверка в игре:** дважды `write=ok verify=ok flush=ok`, на экране без изменений (TASK-009).
- **4a, продолжение (TASK-009, v2.9.5) — шаги 1–5 исполнены, ждут проверки в игре.** Решающий тест `CyrillicFont = "face"`: у записи `Title` в `Font_Aleo.CompositeFont.DefaultTypeface` меняется `FontFaceAsset` (по умолчанию на face `Regular`, флаг `CyrillicTitleFace`), SDF не трогается, Title → Regular не делается. `face`/`cultures` пишутся на кадре 0 с повтором в `after_main`, в логе `applied_at`. Флаг `CyrillicFlush = "culture"` — второй сброс кэша сменой культуры. Если Title изменится — верна H2 (правка доходит, замена face — решение); если нет даже с `CyrillicFlush` — H1, путь «CompositeFont из Lua» закрыт, остаётся 4b. **Проверка в игре: сработало (H2)**, `applied_at=load`.
- **4a, завершение (TASK-010, v2.9.6) — шаги 1–4 исполнены, ждут проверки в игре.** `face` — режим по умолчанию (откат — `typeface`): одной копией `CompositeFont` заменяются face у `Title` → `Regular`, `Title_SDF` и `Title_SDF_HeadName` → `Regular_SDF` (имена над NPC, описание задания), с проверкой каждой записи и откатом всех. Удалены `subfont`, `cultures`, `CyrillicCultureSubs`, `CyrillicFaceCandidates`, флаг `CyrillicFlush` и проба `FInt32Range` (Init.lua, AbsruDiagnostics.lua, CollectDiagLogs.ps1).
- **4b (необязательно; только если нужен шрифт с засечками, которого нет в игре; в TASK-006 не делается):**
  - (a) пробный legacy-`.pak` с одним Lua-файлом: грузит ли игра дополнительные паки (Init.lua пробует `require` и пишет `pak-probe ok/miss`);
  - (b) при успехе — IoStore-контейнер **только с новым** `UFontFace` (Bitter / PT Serif) по собственному пути `/Game/AbsoluteRU/Fonts/…`; ассеты игры (`Font_Aleo` и др.) не заменять. Подключение — как источник face для записи `Title` в режиме `face` (`CyrillicTitleFace`, 4a; загрузка по пути с запасным `Aleo_Regular`, если пак не загрузился). Нужен UE той же версии для кука `UFontFace`;
  - контейнеры игры зашифрованы, `.upak` — собственный формат, AES-ключа нет; инструменты (repak / UnrealPak / FModel / retoc) скачивает пользователь.

### 5. Подгонка текста по измерению — `measure` откачен в `legacy`, `cap` ждёт проверки (TASK-013)
- **Проверка v2.9.7 (2026-09-25):** `measure` хуже v2.9.6 — 1018 переполнений против 251, текст крупнее, блоки разъезжаются; с `TextFit = "legacy"` вид как в v2.9.6. Причины: старт с авторского размера и бюджет авторазмерного слота по родителю, который растёт вместе с текстом ([TASK-013](TASK-013-text-fit-cap.md), LESSONS). С v2.9.8 `TEXT_FIT_MODE = "legacy"`.
- **`cap` (v2.9.9, dev-флаг `TextFit = "cap"`):** размер и перенос legacy — потолок; уменьшение только по разметке исходного текста (фиксированный слот; ширина исходного × 1,15, высота × 1,25), без бюджета по родителю; нет мерки — `TextFitNoBudget`, размер legacy. Если `cap` не хуже `legacy` и переполнений не больше, чем в v2.9.6, сделать его режимом по умолчанию отдельной правкой; `measure` затем удалить.
- Техдолг: `NestedEarlyMsMax = 23` мс в сессии v2.9.7 (критерий ≤ 8). `EarlyNested` не трогать без данных: с ним вид как в v2.9.6.
- Ниже — исходный план TASK-011 (v2.9.7).
- `Init.lua`, `runtimeFixes.TextFit`: авторский размер без +2, авторский перенос, у кириллицы `LetterSpacing = max(0, авторский)`; размер только уменьшается по замеру (`ForceLayoutPrepass` + `GetDesiredSize` против своего фиксированного слота или, у авторазмера, до края родителя, но не уже исходного текста), минимум max(12, 0,6 × авторский), не больше 2 перезамеров, нулевая геометрия — отложенный замер (2 мс на тик). - Ранний перевод вложенных компонентов в их `Open` / `Refresh` (`panelTextRepair:RepairNestedEarly`, dev-флаг `EarlyNested = false`). `delayed` и оставшиеся extended убирать отдельной задачей по `late.md` сессии проверки.

## Прочее
- `tools/PackageRelease.ps1 -Publish` падает на новом теге: `gh release view` для несуществующего релиза пишет в stderr, а при `$ErrorActionPreference = 'Stop'` в PowerShell 5.1 это прерывает скрипт до `gh release create` (v2.9.6 публиковался вручную). Проверять существование релиза через `gh api` / `try`, без `*> $null` под Stop. Попутно: при обрыве загрузки `gh release create` оставляет черновик — повторный запуск создаёт второй.
- В `build/` лежат старые архивы v2.6–v2.9.0 (не в git). Пользователь удалит их сам.
